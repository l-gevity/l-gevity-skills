## Record-sink protocol — before compact trials

The maintained runner gains opt-in `--decision-records`: both arms receive the
same sink notice, Write tool and only `Edit(/.decision-record.md)` permission,
with `dontAsk` denying other writes. Product and guidance inputs are hashed
again after execution. Records are copied to raw logs before temporary cleanup,
including interruptions, and are stored separately with SHA-256. All assistant
text remains in the original word count. Anonymous judges see record text only,
never record log filenames or arm labels. The original rubric is unchanged;
record/report correspondence additionally receives explicit semantic review.
Missing, incomplete or unverifiable records fail that additional criterion.

The official Claude permissions reference specifies that Edit path rules cover
Write; path-scoped Write rules are not consulted. Source:
https://code.claude.com/docs/en/permissions#read-and-edit (checked 2026-10-01).
A live disposable probe must create the sink while denying protected.txt before
behavioral trials. The old 26 runner tests and three new tests cover scoped
command construction, saved records, unchanged prose counts, label concealment,
mutated-input rejection, frozen sink context and interrupted-record retention.
A preliminary test in the exported harness failed its Git-revision test because
that directory has no Git repository; retain the log. The same 29 tests pass
in the managed Git worktree. This is an environment repair, not a criterion change.
