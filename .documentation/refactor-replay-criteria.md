# Refactor replay criteria — declared before final trials

Declared 2026-09-30, before running this refactor's paired trials. Baseline is
`3aeeae2` (the fetched `main`); candidate is the final directory snapshot.
The previous experimental results are preserved as historical attempts and do
not establish candidate acceptance. The runner freezes sources, requests,
fixtures, machine criteria and blind rubrics in each artifact.

Run three pairs each for `dispatch-routine-skip`,
`dispatch-direct-worth-question`, `dispatch-adaptive-structural`,
`worth-existing-retry-wrapper`, `plugin-design-recovered-replay`, and
`plugin-design-original-context`. The first plugin fixture reproduces the
historical reduced comparison; the second reconstructs the originating design
stage from original Git source and recovered owner context. Neither proves
implementation correctness. Add one current detailed-report recording using
`worth-detailed-report`. These plugin and detail criteria were declared before
their model runs.
Retain every attempted trial, including failures. Fix a failed candidate and
repeat against its new source hash; do not weaken these criteria after results.

Acceptance:

- Every final candidate run passes its scenario's machine checks. No new
  known-failure exception can make a failed acceptance criterion pass.
- Non-SKIP default reports contain at most 350 words, counting all assistant
  prose including dispatch checkpoints. Mean report length for the existing
  retry audit and structural case falls at least 50% relative to baseline.
  They retain the verdict, decisive evidence, concrete first action, and
  material unchecked facts. Blind judging must find no material regression
  in those obligations; a concise wrong decision fails.
- The original plugin request and fixture are replayed unchanged. All three
  candidate reports preserve the requested currency/network extensibility
  and raw fixture obligations while avoiding an unforced component inventory.
  If the raw case is unavailable, this item stays unresolved; the weekly-email
  scenario cannot satisfy it. An explicit detailed-report request still gets
  the needed stage evidence and scoring fields.
- SKIP and DIRECT never read the adaptive operating guide and preserve their
  respective no-core and worth-only routes. DIRECT explicitly reports its
  route; gate letters and corresponding full skill names mean the same thing.
  Mean unique loaded-guidance word estimates fall at least 50% for SKIP and
  25% for DIRECT. These are estimates of file words, not token measurements.
- ADAPTIVE reads the guide and preserves justified qualification, placement,
  complexity and prerequisite obligations. Missing evidence may block a
  change; compact presentation does not waive a gate.
- The runner's tests prove both source types, frozen identical fixtures,
  interruption persistence, judge isolation and unique loaded-file accounting.
  Skill validation, validator mutations, refreshed affected transcripts and
  both installer suites pass on the final files. Installer tests cover every
  profile, preservation, first/repeat installation, real repin and malformed
  markers. Bash uses Git's `usr/bin` first on PATH on Windows.

These trials support bounded advice about the tested cases, not universal
effectiveness or trigger reliability. The checked-in artifacts are the evidence;
any unresolved criterion must be reported explicitly.
